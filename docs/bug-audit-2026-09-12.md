# 2026-09-12 残留问题修复

基于已提交的 21c31ef 继续处理，开始时工作区干净。本轮修复两类有复现证据的 Agent 通讯缺陷，并清理上轮留下的严格 Clippy 与 Rust 格式检查阻塞。

## 功能修复

### Agent 占用状态提前释放

conversation.invalidate 和 conversation.read 在注销或权限失效时直接从 activeAgents 删除参与者。旧异步请求尚未结束时，新的发送/配置请求就可能进入；注销一个空闲会话的另一参与者，也会把正在其他会话中工作的共享 Agent 解锁。

现在只有 run.finally 在旧请求真正结束后释放占用状态。取消、注销和权限失效仍立即断开对应协议连接、停止后续转发，但不能解锁其他会话的运行请求。

### 保存失败留下未持久化状态

消息、配置和新会话先修改内存，再保存文件；写入失败时内存不回滚。消息会残留 running 状态和已消费的 requestId，实际没有启动执行，但后续重试被忽略或拒绝；失败配置和新会话也会继续出现在读取结果中。

现在失败时还原对应内存状态，配置的旧连接仅在保存成功后关闭；初次消息保存失败后，同一 requestId 可以重试。已发生投递的失败仍不自动重发。

## 原生检查清理

- Bridge 启动改为接收现有 AgentBridgeConfig，避免拆散传递九个参数；scope 解析、端口、令牌、SFTP root、审计和权限模式语义保持不变。
- 修正冗余闭包、默认枚举实现、Path 参数、contains/is_some_and、测试中不必要的可变借用等 Clippy 阻塞。
- 测试模块移动至文件尾；统一 Rust 格式。Runtime 的五个格式修改文件和 agent_hub.rs 已逐一比较原版本的 rustfmt 输出，确认无逻辑变化。
