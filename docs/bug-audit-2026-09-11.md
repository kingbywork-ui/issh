## 已修复问题

| 等级 | 触发条件和影响 | 修复位置与行为 |
| --- | --- | --- |
| P1 | 终端订阅发生三次分散的临时失败，成功订阅不清零计数；达到阈值后调用 session.close，可能杀死仍在运行的 shell 和任务。连续管道失败也不能证明 shell 已结束。 | App.svelte 的 pollOutput：成功后重置错误和提示状态；失败只提示并重试，保留终端；Runtime 明确报告退出时仍按既有行为关闭。 |
| P1 | SFTP 根目录只通过本机 PathBuf.starts_with 检查。/allowed/../secret 可绕过，指向根目录外的符号链接也未校验。 | Agent Bridge 按 POSIX 路径检查并传入受信任配置 root；isshd 在读、写、列目录前使用远端 REALPATH 检查根目录和目标路径。写入新文件只允许末级不存在，使用 LSTAT 区分悬空链接；权限错误不回退。能力 sftp.scopedPaths 防止旧 Runtime 忽略新字段。返回列表保留调用者路径以支持根目录别名。 |
| P1 | SSH 命令输出超过 64 KiB，边界落在中文或 emoji 内，直接字节切片触发 Rust panic。发布配置 panic=abort，可能退出整个应用。 | agent_bridge.rs 的输出预览退到 UTF-8 字符边界再截断，完整输出缓存保留。 |
| P1 | ssh.execReadonly 的桌面管道超时固定为 10 秒；后台任务配置可长达数分钟，因此任务仍在执行时前端已经报失败。 | lib.rs 的 request_timeout 按执行时限加 5 秒计算；isshd 与桌面统一将执行时限限制在 1 ms–1 小时，为 Runtime 的额外 2 秒收尾留出余量，极端整数输入不生成无界计时器。 |
