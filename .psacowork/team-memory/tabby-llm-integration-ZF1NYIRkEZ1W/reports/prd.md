## 1. 产品概述

### 1.1 功能背景

Tabby 是一款基于 Electron + Angular 的跨平台终端模拟器，以高度可定制、插件丰富、界面美观著称。随着大语言模型（LLM）技术的成熟，终端用户迫切需要一种更智能、更高效的命令交互方式。当前终端用户面临以下痛点：

- **命令记忆成本高**：Linux/Unix 命令参数繁多，用户经常需要查阅文档或搜索引擎
- **自然语言到命令的转换门槛高**：用户知道"想做什么"，但不知道"命令怎么写"
- **补全体验差**：传统 Tab 补全仅能基于文件路径，无法理解语义上下文
- **学习效率低**：新手用户难以从命令输出中理解问题原因

### 1.2 目标用户画像

| 用户类型 | 描述 | 核心诉求 | 预估占比 |
|---------|------|---------|---------|
| **初级开发者** | 刚接触命令行，对命令不熟悉 | 用自然语言描述需求，获得正确命令 | 30% |
| **中级开发者** | 熟悉常用命令，但参数容易忘 | 快速补全命令参数，减少查阅文档 | 40% |
| **高级开发者** | 命令行重度用户，追求效率 | 基于上下文智能补全，减少重复输入 | 20% |
| **DevOps/运维** | 需要处理复杂的脚本和管道 | 复杂命令生成、多步骤脚本辅助 | 10% |

### 1.3 核心价值主张

> **"让终端理解你的意图，而不仅仅是你的输入。"**

Tabby 大模型集成旨在通过 AI 能力，将终端从"被动执行工具"升级为"智能交互伙伴"：

1. **降低学习成本**：新手用户可以用自然语言描述需求，无需记忆复杂命令语法
2. **提升操作效率**：自动补全减少键盘输入，上下文感知提升补全准确率
3. **增强命令理解**：AI 辅助解释命令含义，帮助用户理解复杂操作
4. **减少错误操作**：智能提示潜在风险命令，降低误操作概率

### 1.4 与竞品的差异化优势

| 竞品/方案 | 自动补全 | 白话描述 | 本地部署 | 上下文感知 | 安全性 |
|-----------|---------|---------|---------|-----------|--------|
| **Tabby + LLM** (本项目) | ✅ 语义级补全 | ✅ 自然语言转换 | ✅ 支持 Ollama | ✅ 终端上下文 | ✅ 本地过滤 |
| Warp AI | ✅ 基础补全 | ✅ 自然语言 | ❌ 仅云端 | ⚠️ 有限 | ⚠️ 数据上传 |
| GitHub Copilot CLI | ✅ 命令补全 | ✅ 自然语言 | ❌ 仅云端 | ⚠️ 有限 | ⚠️ 数据上传 |
| Fig (Amazon Q) | ✅ 命令补全 | ❌ 不支持 | ❌ 仅云端 | ✅ 丰富 | ⚠️ 数据上传 |
| iTerm2 + OpenAI | ⚠️ 需插件 | ⚠️ 需插件 | ❌ 仅云端 | ❌ 无 | ⚠️ 数据上传 |
| 传统 Tab 补全 | ❌ 仅文件路径 | ❌ 不支持 | ✅ 本地 | ❌ 无 | ✅ 安全 |

**核心差异化优势**：

1. **开源 + 本地部署**：支持 Ollama 等本地模型，敏感数据不上云
2. **深度终端上下文**：基于当前目录、环境变量、历史命令等上下文进行智能补全
3. **非侵入式体验**：AI 功能可开关，不影响传统终端操作习惯
4. **多模型支持**：OpenAI / Anthropic / 通义千问 / Ollama 等多种模型可选
5. **隐私优先**：敏感信息本地过滤，用户可控数据分享范围

## 2. 功能定义

### 2.1 自动补全命令 (AI Autocomplete)

#### 2.1.1 功能概述

用户在终端输入命令时，系统基于当前输入上下文、终端状态、历史命令等信息，通过大模型实时生成智能补全建议，并以浮层面板形式展示，用户可通过键盘快速选择和应用。

#### 2.1.2 触发方式

| 触发方式 | 说明 | 默认状态 |
|---------|------|---------|
| **自动触发** | 输入达到最小触发字符数（默认 2 字符）后，延迟触发补全 | 开启 |
| **手动触发** | 快捷键 `Ctrl+Shift+A` 手动触发补全 | 开启 |
| **Tab 增强** | 当传统 Tab 补全无结果时，自动 fallback 到 AI 补全 | 关闭（可选配置） |
| **命令行前缀** | 输入特定前缀（如 `//`）触发 AI 补全模式 | 关闭（可选配置） |

#### 2.1.3 展示形式

```
┌─────────────────────────────────────────┐
│ 终端输出区域                             │
│                                         │
│  $ git com│                              │
│  ┌─────────────────────────────────┐   │
│  │ ▶ git commit -m "message"       │   │  ← AI 建议（高置信度）
│  │   git commit --amend             │   │
│  │   git config --global ...        │   │
│  │   ─────────────────────────────  │   │
│  │   git checkout main              │   │  ← 历史命令
│  │   git push origin main           │   │
│  └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

- **浮动面板**：跟随光标位置，不遮挡终端输出
- **分类展示**：AI 建议 / 历史命令 / 文件路径 / 系统命令
- **置信度可视化**：通过颜色条或百分比显示 AI 对建议的置信度
- **高亮匹配**：用户输入部分在建议中高亮显示

#### 2.1.4 交互流程

```
用户输入 ──▶ 防抖延迟(300ms) ──▶ 收集上下文 ──▶ LLM 请求
    │                                               │
    │                                               ▼
    │                                        解析响应结果
    │                                               │
    │                                               ▼
    │                                        安全检查(过滤危险命令)
    │                                               │
    │                                               ▼
    │                                        展示补全面板
    │                                               │
    └──────────◀ 用户选择(Tab/Enter) ◀────────────┘
                │
                ▼
            应用命令到终端
                │
                ▼
            记录到历史/缓存
```

#### 2.1.5 支持的命令类型和场景

| 命令类型 | 示例 | 说明 |
|---------|------|------|
| **Git 命令** | `git commit`, `git rebase -i HEAD~3` | 基于 Git 上下文的智能补全 |
| **Docker 命令** | `docker run -d --name ...` | 容器名称、镜像、参数补全 |
| **文件操作** | `find . -name "*.js" -size +1M` | 文件路径、通配符、参数补全 |
| **系统管理** | `systemctl status nginx` | 服务名、状态参数补全 |
| **网络命令** | `curl -X POST -H "Content-Type..."` | HTTP 方法、Header 补全 |
| **数据库** | `psql -U postgres -d mydb` | 数据库名、用户名补全 |
| **自定义脚本** | `./deploy.sh --env=prod` | 基于项目上下文的脚本参数补全 |

#### 2.1.6 准确率和性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| **首屏响应时间** | ≤ 500ms | 从用户停止输入到首条建议展示 |
| **完整响应时间** | ≤ 2000ms | 所有建议完整展示（含解释） |
| **Top-1 准确率** | ≥ 70% | 首条建议为用户期望命令的比例 |
| **Top-3 准确率** | ≥ 85% | 前三条建议包含用户期望命令的比例 |
| **误触发率** | ≤ 5% | 用户不需要时触发补全的比例 |
| **缓存命中率** | ≥ 60% | 通过本地缓存减少 API 调用 |

### 2.2 白话描述命令 (NL2Command)

#### 2.2.1 功能概述

用户通过自然语言描述想要执行的操作，系统通过大模型将自然语言转换为对应的终端命令，并提供命令解释、风险提示和替代方案。

#### 2.2.2 输入方式

| 输入方式 | 说明 | 快捷键 |
|---------|------|--------|
| **底部输入栏** | 终端底部固定输入栏，切换为自然语言模式 | `Ctrl+Shift+N` |
| **浮动输入框** | 快捷键触发浮动输入框，输入后转换为命令 | `Ctrl+Shift+N` |
| **命令行前缀** | 在终端输入 `//` 前缀，后续内容视为自然语言 | 可配置 |
| **右键菜单** | 选中终端文本，右键"用自然语言描述" | - |

#### 2.2.3 转换流程

```
┌─────────────────────────────────────────┐
│  自然语言输入                            │
│  > 查找当前目录下所有大于1MB的js文件      │
│                                         │
│  [转换中...]                            │
│                                         │
│  转换结果:                               │
│  ┌─────────────────────────────────┐   │
│  │ $ find . -name "*.js" -size +1M │   │
│  │                                 │   │
│  │ 说明: 在当前目录及子目录中查找  │   │
│  │ 所有扩展名为 .js 且大小超过 1MB │   │
│  │ 的文件。                         │   │
│  │                                 │   │
│  │ ⚠️ 注意: 大文件搜索可能耗时较长  │   │
│  │                                 │   │
│  │ 替代方案:                        │   │
│  │ 1. find . -name "*.js" | xargs │   │
│  │    ls -lh | awk '$5 > 1048576' │   │
│  └─────────────────────────────────┘   │
│                                         │
│  [使用此命令] [查看替代方案] [取消]     │
└─────────────────────────────────────────┘
```

#### 2.2.4 结果展示

| 展示元素 | 说明 |
|---------|------|
| **转换命令** | 高亮显示的命令文本，可复制 |
| **命令解释** | 用中文/英文解释命令的作用和参数含义 |
| **风险提示** | 标记潜在风险（如删除、覆盖、权限操作） |
| **替代方案** | 提供 1-3 个等效替代命令 |
| **置信度** | AI 对转换结果的置信度百分比 |

#### 2.2.5 支持的自然语言复杂度

| 复杂度 | 示例 | 支持状态 |
|--------|------|---------|
| **简单描述** | "列出当前目录文件" | ✅ 支持 |
| **条件筛选** | "查找昨天修改过的文件" | ✅ 支持 |
| **多步骤操作** | "先备份数据库，然后压缩并上传到服务器" | ✅ 支持 |
| **管道组合** | "查找所有图片文件并按大小排序" | ✅ 支持 |
| **条件逻辑** | "如果文件存在则删除，否则创建" | ⚠️ 部分支持 |
| **循环操作** | "遍历所有子目录并执行 npm install" | ⚠️ 部分支持 |
| **正则匹配** | "查找包含 email 格式的行" | ✅ 支持 |

#### 2.2.6 准确率要求

| 指标 | 要求 | 说明 |
|------|------|------|
| **简单描述准确率** | ≥ 90% | "列出文件"等基础描述 |
| **复杂描述准确率** | ≥ 75% | 多条件、多步骤描述 |
| **命令可执行率** | ≥ 85% | 生成的命令在目标环境中可直接执行 |
| **用户采纳率** | ≥ 60% | 用户选择使用生成命令的比例 |

### 2.3 两个功能之间的关系

```
┌─────────────────────────────────────────────────────┐
│                   Tabby AI 功能矩阵                  │
├─────────────────────────────────────────────────────┤
│                                                     │
│   用户输入 ──▶ 自动补全 (Autocomplete)              │
│      │                                              │
│      ├─ 用户知道命令开头，需要补全参数 ──▶ 实时浮层  │
│      │                                              │
│      └─ 用户不确定命令 ──▶ 切换到白话描述            │
│                              │                      │
│                              ▼                      │
│                    白话描述 (NL2Command)            │
│                              │                      │
│                              ├─ 自然语言输入        │
│                              ├─ AI 转换为命令        │
│                              └─ 结果应用到终端       │
│                                                     │
│   优先级: 自动补全 P0 > 白话描述 P0                 │
│   协同: 自动补全可调用白话描述的历史结果优化推荐      │
│         白话描述生成的命令可被自动补全学习           │
└─────────────────────────────────────────────────────┘
```

| 维度 | 自动补全 | 白话描述 |
|------|---------|---------|
| **触发时机** | 输入过程中实时触发 | 用户主动触发 |
| **交互模式** | 被动辅助 | 主动查询 |
| **输入形式** | 命令片段 | 自然语言 |
| **输出形式** | 命令补全建议 | 完整命令 + 解释 |
| **使用场景** | 已知命令，需补全 | 不确定命令，需转换 |
| **优先级** | P0（核心功能） | P0（核心功能） |
| **依赖关系** | 独立运行 | 可调用自动补全的上下文 |

## 3. 用户场景和使用案例

### 3.1 场景一：新手开发者学习 Git 命令

**目标用户**: 初级开发者 (用户画像 A)

**使用场景**: 小明是刚入职的前端工程师，对 Git 命令不熟悉，需要频繁提交代码但记不住完整命令。

**操作步骤**:
1. 小明在终端输入 `git com`
2. Tabby AI 自动弹出补全面板，显示：
   - `git commit -m "message"` (AI 建议)
   - `git commit --amend` (AI 建议)
   - `git config --global ...` (AI 建议)
3. 小明按 ↓ 选择第一条，按 Tab 确认
4. 命令自动补全为 `git commit -m ""`，光标定位到引号内
5. 小明输入提交信息并执行

**预期结果**: 小明无需记忆完整命令语法，通过 AI 辅助快速完成 Git 操作。

### 3.2 场景二：查找并处理日志文件

**目标用户**: 中级开发者 (用户画像 B)

**使用场景**: 小红需要查找服务器上的错误日志，并按时间排序，但她不记得具体的 find + sort 组合命令。

**操作步骤**:
1. 小红按 `Ctrl+Shift+N` 打开白话描述面板
2. 输入："查找当前目录下所有 .log 文件，按修改时间排序，显示前 10 个"
3. AI 处理并返回：
   ```
   find . -name "*.log" -type f -mtime -7 | xargs ls -lt | head -n 10
   ```
4. 小红查看命令解释和风险提示
5. 确认后命令自动填入终端

**预期结果**: 复杂的 find/xargs/sort 组合命令通过自然语言快速生成，减少查阅文档时间。

### 3.3 场景三：批量重命名文件

**目标用户**: 高级开发者 (用户画像 C)

**使用场景**: 老王需要将一批图片文件从 `IMG_001.jpg` 重命名为 `product_001.jpg`。

**操作步骤**:
1. 老王输入 `for file in IMG_*.jpg; do`
2. AI 自动补全面板显示循环体建议：
   - `mv "$file" "${file/IMG_/product_}"` (AI 建议)
   - `rename 's/IMG_/product_/' *.jpg` (AI 建议)
3. 老王选择第二条（更简洁）
4. 命令自动补全，老王执行

**预期结果**: 基于 Bash 循环上下文的智能补全，提供多种实现方案。

### 3.4 场景四：Docker 容器管理

**目标用户**: DevOps 工程师 (用户画像 D)

**使用场景**: 小张需要查看所有运行中的容器，并进入特定容器执行命令。

**操作步骤**:
1. 小张输入 `docker ps`
2. 查看输出后，输入 `docker exec -it `
3. AI 补全面板显示：
   - 运行中容器列表（从 docker ps 输出解析）
   - 常用命令：`bash`, `sh`, `/bin/bash`
4. 小张选择容器 ID 和 shell，快速完成命令

**预期结果**: AI 基于终端输出上下文，提供动态的、上下文相关的补全建议。

### 3.5 场景五：安全命令检查

**目标用户**: 所有用户

**使用场景**: 用户输入了 `rm -rf /`，AI 检测到潜在危险命令并给出警告。

**操作步骤**:
1. 用户输入 `rm -rf /`
2. AI 检测到危险命令模式
3. 在命令执行前弹出警告：
   ```
   ⚠️ 危险命令检测
   
   您即将执行: rm -rf /
   
   该命令将递归删除根目录下的所有文件，
   可能导致系统无法恢复！
   
   [确认执行] [取消] [查看安全替代方案]
   ```
4. 用户选择"查看安全替代方案"
5. AI 提供：
   - `rm -rf ./target_directory` (限定范围)
   - `rm -ri /path/to/dir` (交互式确认)

**预期结果**: 防止误操作，保护用户数据安全。

## 4. UI/UX 需求

### 4.1 功能入口位置

| 入口位置 | 功能 | 说明 |

## 5. 非功能需求

### 5.1 性能要求

#### 5.1.1 响应时间

| 场景 | 目标 | 可接受上限 | 优化策略 |
|------|------|-----------|---------|
| **自动补全首屏** | ≤ 300ms | ≤ 500ms | 本地缓存 + 预加载 |
| **自动补全完整** | ≤ 1000ms | ≤ 2000ms | 流式响应 |
| **白话描述转换** | ≤ 1500ms | ≤ 3000ms | 异步处理 + 进度条 |
| **面板打开** | ≤ 50ms | ≤ 100ms | 预渲染 |
| **面板关闭** | ≤ 30ms | ≤ 50ms | 动画优化 |

#### 5.1.2 并发处理

- 最大并发 LLM 请求数：**3**（可配置）
- 请求队列长度：**10**（超过则丢弃最旧请求）
- 同一输入的重复请求：**自动合并**

#### 5.1.3 资源占用

| 资源 | 目标 | 说明 |
|------|------|------|
| **内存占用** | ≤ 50MB | AI 相关服务和缓存 |
| **CPU 占用** | ≤ 5% | 空闲时 |
| **磁盘缓存** | ≤ 100MB | 本地缓存文件 |
| **网络带宽** | ≤ 10KB/请求 | 平均请求大小 |

### 5.2 安全要求

#### 5.2.1 隐私保护

| 层级 | 策略 | 说明 |
|------|------|------|
| **数据脱敏** | 三级脱敏策略 (none / basic / strict) | 用户可配置 |
| **敏感信息过滤** | 正则匹配 + 本地替换 | API Key、Token、密码、SSH Key、IP、邮箱 |
| **本地优先** | 支持 Ollama 本地模型 | 敏感数据不上云 |
| **传输加密** | HTTPS / TLS 1.3 | 云端 API 通信 |
| **审计日志** | 记录 API 调用（可选） | 用户可开启/关闭 |

#### 5.2.2 敏感命令过滤

| 命令类型 | 示例 | 处理方式 |
|---------|------|---------|
| **极度危险** | `rm -rf /`, `mkfs`, `dd if=/dev/zero` | 拦截 + 弹窗警告 |
| **高风险** | `rm -rf`, `chmod 777 -R /` | 警告 + 需要确认 |
| **权限操作** | `sudo`, `chown -R` | 提示确认 |
| **网络操作** | `curl ... | sh`, `wget ... | bash` | 风险提示 |

#### 5.2.3 数据安全

- **API Key 存储**：加密存储在本地，不明文保存
- **命令历史**：本地存储，不上传云端（除非用户明确授权）
- **缓存数据**：定期清理，支持手动清除
- **崩溃报告**：不包含终端内容，仅包含错误堆栈

### 5.3 可配置性

#### 5.3.1 配置项列表

## 6. 成功指标和衡量方式

### 6.1 KPI 定义

| KPI | 目标值 | 衡量方式 | 数据收集 |
|-----|--------|---------|---------|
| **功能启用率** | ≥ 50% | 启用 AI 功能的用户数 / 总用户数 | 配置项统计 |
| **日活跃使用率** | ≥ 30% | 每日使用 AI 功能的用户数 / 总用户数 | 事件埋点 |
| **自动补全触发率** | ≥ 40% | 触发补全的会话数 / 总会话数 | 事件埋点 |
| **自动补全采纳率** | ≥ 60% | 采纳建议的次数 / 触发补全的次数 | 事件埋点 |
| **白话描述使用率** | ≥ 20% | 使用白话描述的用户数 / 总用户数 | 事件埋点 |
| **白话描述采纳率** | ≥ 60% | 采纳生成命令的次数 / 使用次数 | 事件埋点 |
| **Top-1 准确率** | ≥ 70% | 首条建议正确的比例 | 用户反馈 + 日志分析 |
| **Top-3 准确率** | ≥ 85% | 前三条建议包含正确答案的比例 | 用户反馈 + 日志分析 |
| **平均响应时间** | ≤ 1000ms | 从触发到展示建议的平均时间 | 性能监控 |
| **用户满意度 (CSAT)** | ≥ 4.0/5.0 | 用户评分 | 应用内问卷 |
| **NPS 评分** | ≥ 30 | 净推荐值 | 应用内问卷 |
| **错误率** | ≤ 2% | 失败请求数 / 总请求数 | 日志监控 |

### 6.2 A/B 测试方案

#### 6.2.1 测试目标

| 测试项 | 对照组 | 实验组 | 衡量指标 |
|--------|--------|--------|---------|
| **自动补全触发延迟** | 300ms | 500ms / 200ms | 采纳率、误触发率 |
| **建议数量** | 5 条 | 3 条 / 7 条 | 采纳率、选择时间 |
| **展示形式** | 列表 | 卡片式 | 采纳率、用户满意度 |
| **白话描述位置** | 底部面板 | 浮动面板 | 使用率、完成时间 |
| **置信度显示** | 不显示 | 显示 | 采纳率、用户信任度 |

#### 6.2.2 测试流程

1. **分组**: 随机将用户分为对照组和实验组（各 50%）
2. **灰度发布**: 先向 10% 用户发布，观察 1 周
3. **数据收集**: 收集 2 周数据
4. **分析评估**: 对比关键指标，判断实验组是否优于对照组
5. **全量发布**: 实验组效果优则全量发布，否则回滚或调整

### 6.3 数据收集和分析计划
