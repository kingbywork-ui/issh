# Tabby 大模型集成 — 综合分析报告

## 项目背景
在 Tabby 终端模拟器中对接大模型，实现**自动补全命令**和**白话描述命令**两大核心功能。

---

## 一、前端方案（已完成 ✅）

### 技术栈
- **框架**: Angular 15 + TypeScript 4.9
- **UI 组件库**: ng-bootstrap 14 (Bootstrap 5)
- **终端引擎**: xterm.js v5.x
- **状态管理**: RxJS + Angular DI
- **构建工具**: Webpack 5

### 核心组件设计

#### 1. 自动补全组件 (AutocompletePanelComponent)
- **位置**: 浮动面板，跟随终端光标
- **交互**: ↑↓选择, Tab/Enter确认, Esc关闭
- **展示**: 命令分类（command/file/history/ai）、置信度条
- **触发**: 输入时自动触发（可配置防抖延迟）

#### 2. 白话描述组件 (NL2CommandPanelComponent)
- **位置**: 底部弹出面板，不遮挡终端输出
- **流程**: 自然语言输入 → LLM转换 → 命令展示 → 用户确认
- **交互**: Enter确认, Esc关闭

#### 3. AI 智能输入栏 (AIInputBarComponent)
- **模式**: 普通模式 / 智能补全 / 自然语言
- **切换**: 下拉菜单或快捷键

### 服务层 (LLMService)
```typescript
// 核心API
getAutocompleteSuggestions(request) → 命令补全建议
convertNaturalLanguage(request) → 自然语言转命令
streamAutocomplete(request) → 流式实时补全
```

### 热键配置
| 热键 | 功能 |
|------|------|
| Ctrl+Shift+A | 切换AI自动补全 |
| Ctrl+Shift+N | 打开自然语言命令转换 |
| Tab/Enter | 接受建议 |
| Esc | 关闭面板 |

### 技术难点与解决方案
| 难点 | 解决方案 |
|------|----------|
| xterm.js 光标追踪 | onData监听+正则匹配当前行 |
| 浮层定位 | 计算字符尺寸和行高 |
| Angular 变更检测性能 | NgZone.runOutsideAngular |
| LLM API延迟 | 流式响应+防抖+本地缓存 |
| 敏感命令安全 | 本地过滤规则，不上传云端 |

### 开发顺序建议
1. **Phase 1**: LLM Service层 + 配置项
2. **Phase 2**: AutocompletePanel组件 + xterm.js集成
3. **Phase 3**: NL2CommandPanel组件
4. **Phase 4**: 性能优化 + 错误处理 + 配置持久化

## 二、产品方案（进行中 ⏳）

### 功能定义
- **目标用户**: 终端用户，特别是需要频繁输入复杂命令的开发者
- **核心价值**: 降低命令记忆成本，提升终端操作效率
- **使用场景**:
  - 场景1: 用户记得命令开头，需要补全参数
  - 场景2: 用户用自然语言描述需求，系统转换为命令
  - 场景3: 用户不确定命令语法，需要AI辅助

### 功能优先级
1. **P0 - 自动补全**: 基于当前输入上下文，实时提供命令补全建议
2. **P0 - 白话描述**: 自然语言输入，转换为终端命令
3. **P1 - 命令解释**: 对复杂命令进行解释说明
4. **P1 - 历史学习**: 基于用户历史命令习惯优化补全

## 三、后端方案（进行中 ⏳）

### 预期架构
- **LLM API对接**: 支持OpenAI/Claude/通义千问等多 provider
- **本地缓存**: 命令补全结果本地缓存，减少API调用
- **上下文管理**: 维护终端会话上下文，提升补全准确性
- **安全过滤**: 敏感命令本地识别，不上报云端
